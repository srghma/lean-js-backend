**The condition and what follows from it** (`LakeJs/Descends.lean`). `Term.Descends` says: the body of a recursion consults its self-reference only at arguments of strictly smaller measure. It is a property of the emitted term and its environment alone — Lean's `termination_by`, its `decreasing_by` proof and the front end's transcription of either do not occur in it — and it is quantified over every argument environment, so the branches erasure made reachable are included. From it three theorems follow, each proved once at the level of the guarded runner so that no future grammar constructor can invalidate them: the recursion equals its body run with *itself*, with no guard (`Term.fixFun_unfold_of_descends`); the `stuck` term can be replaced by any other without changing a value, i.e. that branch is genuinely **unreachable** (`Term.fix_stuck_irrelevant`); and any Lean function satisfying the same unrolling equation *is* the recursion (`Term.fixFun_eq_of_equation`, `Term.fix_implements_of_equation`).

**The verification-condition calculus** (`LakeJs/DescentVC.lean`). A judgment, `Term.SelfIndepOn`, with one rule per construct of the grammar — application, abstraction, `let`, `if`, constructors, projections, tags, structural size, delay and force, dispatch (with a judgment of its own for the branches), blocks and join points (likewise), and both kinds of call. The `if` rule refines the path condition with the truth of the test in each arm, the `let` rule records the value bound, and the dispatch rules record the matched tag and the fields the branch bound, so that by the time a self call is reached the only goal left is the arithmetic one Lean's `decreasing_by` already discharges. The single construct without a rule is a *nested* recursion, noted as such.

# Summary of changes for run a2bab084-edaf-4d6e-8f1f-dd76afef4162
I wrote `TERM_RANK_FLAKINESS_AND_ALTERNATIVES.md`, an assessment of the current rank-based `Term.fix` design and of the alternatives, and — rather than asserting the flakiness — demonstrated it in the tree.

**The assessment.** The document separates the three obligations a backend has (well-typed, terminating, faithful) and shows that the grammar guarantees the first two by construction while the third rests entirely on `LakeJs/FrontEnd.lean`. It inventories the six derivation steps by which the front end invents a rank — reading the measure out of Lean's packed declaration, pairing measure binders with post-erasure parameters by name or position, transcribing the components, splitting parameters into nesting levels, deciding which level each self call belongs to, and adding one (or multiplying by the clique size) — with file and line references, and notes for each what can go wrong. The key structural point: because termination is enforced by the syntax, a wrong rank cannot produce a hang or an error; it produces the `exhausted` branch's default value, i.e. a silently wrong program.

**Evidence, machine-checked.** The new `RankFlakiness/` library contains two experiments. `AckOpaqueArg.lean` is the project's own Ackermann snapshot with one token changed — the unchanged argument of the inner recursive call written `2 * (m + 1) - (m + 1)` instead of `m + 1`, which Lean accepts with the same `termination_by`. The backend translates it and reports `checked`, but because that expression has no linear normal form the call is classified as a call of the *outer*, `m`-ranked recursion, so the rank runs out. `RankFlakiness/AckOpaqueArgCheck.lean` proves `runAckOpaque 1 1 ≠ ackOpaque 1 1` and that 11 of the 16 inputs of the 4 × 4 square disagree (both by `native_decide`, so with that tactic's axioms alongside the standard ones), and also that `(1,0)` and the whole `m = 0` row agree — which is why small smoke tests miss it. `AckMeasureHelper.lean` is the milder failure: writing the same measure through an identity definition makes the declaration be refused outright.

**The proposals.** Improvements that need no grammar change: refuse instead of defaulting when the call-level analysis cannot decide, make the exhausted branch observable and auto-generate a differential check for every emitted recursion, record the rank decisions in the generated file, and — the real fix at this level — check a descent verification condition *on the emitted term* so a wrong rank becomes a compile error rather than a wrong answer. Grammar-level designs, with a comparison table: a structural recursion constructor whose descent is a scoping/typing condition (no measure at all for the structurally recursive majority of the corpus); a lexicographic measure vector, which deletes the whole currying and level-assignment machinery and makes the Ackermann shape a verbatim transcription; a guarded evaluator that recomputes the measure at each self call and requires a strict decrease, so the front end is only ever asked for what `decreasing_by` already proved; plus the designs considered and rejected (carrying `Acc`, sized types, a separate certificate, clocked type theory). The recommendation is the combination of the three, followed by a seven-step migration with acceptance criteria — including that after step 3 the `AckOpaqueArg` check must flip from "wrong" to "agrees".

The new library builds cleanly and contains no `sorry`; `ARISTOTLE_SUMMARY.md` was left untouched, and all work is committed.
